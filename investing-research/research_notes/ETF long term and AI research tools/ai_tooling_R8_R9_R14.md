## R8 — Which open-source AI/LLM finance repos matter for an ETF watch-report toolkit, what do they need, and which are trending?

### Takeaway
Of the 19 repos examined, only a handful are "research/analysis" tools that run on free data and support Anthropic/Claude natively: **TradingAgents** (Anthropic listed, Yahoo/EDGAR/FRED data, simulated exchange only), **ai-hedge-fund** (Anthropic listed, but needs the paid Financial Datasets API), **Vibe-Trading** (Anthropic plus a `claude-cli` provider, yfinance/FMP/Tiingo, paper trading by default but 18 live-broker connectors), **LangAlpha** (Claude subscription sign-in, Yahoo free default, but it is a brokerage-connected trading harness), and **FinanceDatabase + FinanceToolkit** (no LLM, but the only pair with first-class ETF holdings/sector/overlap analysis and their own hosted MCP servers). Portfolio libraries (quantstats, skfolio, PyPortfolioOpt, Riskfolio-Lib) are LLM-free building blocks with permissive licenses. QuantDinger and AutoHedge are execution-oriented and QuantDinger does not list Anthropic; FinRobot and FinGPT are OpenAI-centric and would need adaptation; Qlib is an ML research platform with no LLM layer and a disabled official dataset. The most "trending" repos in the last 90 days by gittrend.io are TradingAgents (+10.6k stars/30 days), Vibe-Trading (+3.1k/30 days) and QuantDinger (+1.1k/30 days).

## R14 — How to run a daily/monthly ETF report pipeline: schedulers, storage, notifications, cost, rate limits, idempotency

### Takeaway
Four viable schedulers exist for a Claude Code user: (1) Claude Code **cloud scheduled tasks** (1-hour minimum, runs from a GitHub repo clone with connectors, usage billed to the subscription, API trigger available), (2) **Desktop scheduled tasks** (local files/MCP, machine must be awake), (3) **GitHub Actions** cron with `claude-code-action` or plain Python (free minutes on public repos, but documented 5–8 h delays and dropped runs under load; disabled after 60 days inactivity), and (4) local cron/n8n/Cloudflare Worker calling `claude -p --bare` or a Python script. Outputs fit naturally as Markdown committed to the repo (cloud tasks push `claude/` branches and can create PRs; artifacts can also be republished). Notification channels with confirmed limits: Telegram bots (1 msg/s per chat, 20/min in groups, 50 MB files), Discord webhooks (2,000-char content, 10 embeds, file upload), Gmail API (`messages.send` = 100 quota units; 6,000 units/user/min), Resend (3,000 emails/month free per richfolio). Model cost per daily run on the 2026 price list is cents: Haiku 5.5 ($0.10/$0.50 per MTok), Sonnet 5.5 ($2/$10), Opus 5.5 ($4/$20); a 60k-input/5k-output run is roughly $0.01 (Haiku), $0.17 (Sonnet), $0.34 (Opus) before caching. Free data APIs are the binding constraint: Alpha Vantage 25/day, FMP 250/day, EODHD 20/day, Twelve Data 800/day (8/min), Tiingo 50/hour and 1,000/day, Massive 5/min, FRED ~120/min, yfinance unmetered but IP-rate-limited (429s).

### Inferences
- Cost per run (my arithmetic from the published prices; assumes ~60k input tokens of data/prompt and ~5k output, no caching): Haiku 5.5 ≈ $0.006 + $0.0025 ≈ $0.01; Sonnet 5.5 ≈ $0.12 + $0.05 ≈ $0.17; Opus 5.5 ≈ $0.24 + $0.10 ≈ $0.34; Fable 5.1 ≈ $0.60 + $0.25 ≈ $0.85. A multi-turn Claude Code agentic run that re-reads a ~60k prefix across 10 turns pays cache reads at 0.05× on Sonnet 5.5 (~$0.10/MTok), so 10 turns × 60k cached ≈ $0.06 extra; a realistic daily Sonnet 5.5 agentic run therefore lands around $0.20–0.40, i.e. roughly $5–10/month for daily plus monthly reports. Using the 4.7+ tokenizer adds ~30% to token counts. If the run is executed as a cloud/Desktop scheduled task or via `CLAUDE_CODE_OAUTH_TOKEN`, it consumes subscription quota instead of API dollars.
- A daily budget of free data calls: at 25/day Alpha Vantage covers only a short watchlist (e.g. 10 ETF profiles + 5 news-sentiment calls + ~10 macro series) and cannot also serve prices; use yfinance (throttled, cached) for prices, FRED (120/min) for macro, FMP (250/day) or SEC N-PORT for holdings, and reserve Alpha Vantage for ETF_PROFILE/NEWS_SENTIMENT. Monthly deep-dives can batch heavier calls on a separate day to stay under daily caps.
- Because GitHub `schedule:` is documented as best-effort (delays, dropped runs, 60-day auto-disable) and a real ETF-digest project abandoned it, the more reliable free options are: Claude Code cloud scheduled task (1-hour granularity is fine for daily/monthly), a Cloudflare Worker cron hitting `workflow_dispatch` or the task's `/fire` API endpoint, or a local cron/n8n on an always-on machine running `claude -p --bare --permission-prompts none --max-budget-usd 1 --output-format json`.
- Idempotent design from the sources: key each run by trade date (skip if `reports/daily/YYYY-MM-DD.md` already exists), cache raw vendor JSON per date before LLM calls (so re-runs do not re-spend API quota), write a run manifest with cost (`total_cost_usd`) and data-provider status, and mark reports "degraded" when a provider fails rather than failing the whole run.
- Storage: committing Markdown to the repo is the lowest-friction choice because cloud tasks already clone/push the repo; GitHub Pages or an artifact can be layered on top. Notion/Slack/Linear-style connectors are available to cloud tasks only via claude.ai connectors.
